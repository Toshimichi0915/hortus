# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

phi is a terminal coding agent (TypeScript, pnpm workspace): `@phi/core` (providers, tool loop, sessions, plugins) and `@phi/cli` (Ink TUI).

## Commands

```sh
pnpm build          # tsc -b packages/cli (project references build core too)
pnpm dev            # build, then run node packages/cli/dist/index.js
pnpm test           # build, then node --test over packages/*/dist/**/*.test.js
pnpm lint           # biome lint
pnpm format         # biome format --write
```

Tests run from compiled `dist/`, so build first. Single test file: `pnpm build && node --test packages/core/dist/session.test.js` (add `--test-name-pattern "<name>"` to pick one test). Tests use `node:test` + `node:assert/strict`, colocated as `*.test.ts(x)`.

## Conventions

- Source imports use `.ts`/`.tsx` extensions; `rewriteRelativeImportExtensions` rewrites them on emit. ESM only, `verbatimModuleSyntax` (use `import type`), `noUncheckedIndexedAccess`.
- Prefer `interface` over `type` for object shapes; use `type` only for unions, intersections, and other aliases an interface can't express.
- Biome: 2-space indent, 120 cols, double quotes, organized imports.
- `// ponytail:` comments mark deliberate shortcuts with a known ceiling and upgrade path.

## Architecture

- **Provider-neutral messages** (`core/src/llm.ts`): `Message` is `user | assistant | tool`. Each provider (`providers/*.ts`) converts to/from its own API. Assistant messages may carry `raw: { provider, content }`, replayed verbatim only to the same provider (e.g. Anthropic thinking blocks); other providers rebuild from `text`/`toolCalls`. Anthropic sanitizes foreign tool-call ids. OpenRouter is just an `openai`-type secrets entry with an `endpoint`.
- **Plugins** (`plugins.ts`, `builtin.ts`): a plugin's default export is `{ providers?, tools?, on? }`; `on` handles `Events` (`llm.ts`: `session_start`, `text`, `tool_call`, `message`), run in plugin order with mutable payloads. builtin's `session_start` pushes the base system prompt. `builtin` (openai/anthropic + read/write/bash tools) loads first, then every `~/.phi/plugins/<dir>/phi.json` (`name`, `version`, `entrypoint`, `dependencies`/`optionalDependencies` as `{ name: npm-style range }`, checked with `semver`; dependencies load first, missing required ones or cycles throw); later plugins override providers and tools by name. Hosts pass `LoadOptions`: `provided` names (the CLI's `{ "@phi/cli": version }`) satisfy dependencies, version-checked, without loading anything (a directory plugin with such a name is a duplicate); `extra` plugins load last. `loadPlugins` also returns `plugins` in load order, for host keys like the CLI's `cli`. Define tools with the `tool()` helper (zod input schema, converted via `z.toJSONSchema`).
- **Agent loop** (`agent.ts`): `createAgent(opts?: LoadOptions)` loads config and plugins once (a plugin in `opts.extra` runs last; it's how callers observe a run, as `cli.ts` does); its `run(history, { model?, provider? })` resolves provider/model/key per run, emits `session_start` to build the system prompt, then loops up to 50 steps, running tool calls in parallel and emitting `text` / `tool_call` / `message`. `listModels()` lists the models of every secrets.json provider, skipping one whose listing fails. Tool errors and invalid input are returned to the model as `isError` results, not thrown. Model precedence: override → `config.model` (only if the provider is `config.provider`); neither → error.
- **State in `~/.phi`**: `config.json` (provider, model), `plugins/`, `secrets.json` (`{ <name>: { type, apiKey, endpoint? } }`, mode 0600; `type` picks a plugin provider, `<name>` is what `config.provider`/`/model <name>/<model>` select; keys are passed explicitly so SDKs never read env vars), `sessions/<epoch>_<uuid>.jsonl`.
- **Sessions** (`session.ts`): append-only JSONL of entries forming a tree via `parentId`; state is rebuilt by replaying root→leaf through versioned `parsers` (`v` + `type`; unknown lines skipped). Resuming from an earlier entry branches within the same file. `model` entries snapshot both model and provider per branch. Adding a new entry type = new `EntryBody` variant + parser. A `Session` is a read-only zustand/vanilla store (`getState`, `subscribe((state, prev) => …)`); `append` / `setModel` / `setProvider` update it and append to the file, so the two never drift.
- **CLI** (`cli/src`): `index.tsx` starts a new session, or with `-r <uuid>` resumes that one at its last entry (`-r` alone opens `session-picker.tsx`, a list from core's `listSessions` filtered by first user message); `createCli` replays resumed messages into the transcript; it passes `LoadOptions` with `provided: { "@phi/cli": version }` to every plugin load, and registers a `module.registerHooks` resolve hook so plugins' `react` / `ink` / `@phi/*` imports resolve to the host's copies (two Reacts break hooks). `cli.ts` (`createCli`) is the React-free controller: the UI zustand store (`UiState`, including the shown `session`, which `setSession` swaps), the run observer, submit (a `/name arg` line runs that command, an unknown name is reported and stays in the prompt, anything else is a turn) / abort, and `status`, re-resolved by subscribing to the session. `commands.ts` is the `Command` API (`name`, `aliases`, `args`, `complete` → `Candidate`s, `run`: returned text → info line, thrown error → error line) and `parseCommand`; the built-ins `/new` (`/clear`), `/model <provider>/<model>` and `/resume [session]` (like `-r <uuid>`; offers the other sessions newest first, and with no argument takes the first) use nothing a plugin can't, and `cli.commands` is them plus every plugin's `cli.commands`, merged by name (later plugins win). `api.ts` is the public `@phi/cli` module (`CliPlugin`, `Slots`, `Cli`, `Command` / `Candidate`, `useSession` (the shown session) / `useUi`, `useShallow`, `theme`, `usageLine`). A plugin's `cli.statusBar` gets the implementation it replaces as `Default`; `app.tsx`'s `composeSlots` wraps them in load order (later plugins outermost), each in a `Guard` error boundary that falls back and reports. `command-menu.tsx` is the `/` menu under the prompt (`suggest`: matching names, then the typed command's `complete` candidates, exact → prefix → substring; Tab/Enter fill the selected row, Enter on an exact one submits, Esc hides it); `prompt-input.tsx`'s `onKey` lets it take keys first. `app.tsx` is otherwise layout and keys; `status-bar.tsx` is the built-in status bar. `transcript.tsx` does its own wrapping, scrolling, mouse selection and copy (alternate screen + SGR mouse reporting); the store's entries are reprinted to normal scrollback on exit.
